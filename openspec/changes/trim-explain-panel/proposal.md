# 商品說明只留規格，並移除 studio.html 的導覽列

## Why

`add-jan-import` 把 amiami 的商品說明整段（`製品仕様` ＋ `解説`）抓進來，鋪在右欄的面板上，還一併打包成 ZIP 內的 `.txt`。實際上架用過幾輪之後，三件事被證明是多的：

1. **`解説` 用不到**——它是廠商的行銷文案（原型師、彩色師、宣傳詞）。貼進賣場只會把真正要看的規格往下推。
2. **面板標題是重複資訊**——標題就是商品名稱，而同一個名稱已經在左欄「輸出設定」卡上，旁邊還有「用這個命名」可以一鍵填進檔名。右邊再放一次，只是佔掉可讀內容的位置。
3. **ZIP 內的 `.txt` 沒人開**——那份文字的用途是**被貼進賣場的欄位**。面板上按一下「複製全部」就到剪貼簿了；從壓縮檔裡撈一個檔案出來、開起來、再全選複製，是同一件事的長路徑。它還逼出一條例外規則（「有內文時單張也要打包」），讓「單張不打包」多一個要記的前提。

`studio.html` 上方的三頁導覽列是第四件：它是主力工作頁，切去 `index.html` 或 `censor.html` 不是日常動作，而導覽列每次載入都佔著標題上方一整條。

## What Changes

- **擷取層只取 `製品仕様`**：新增 `parseSpec()`，優先以商品頁給規格段落的 id 定位，該 id 不存在時才退回標題文字比對。`解説` 與其餘段落 MUST NOT 進入資料——排除發生在資料層，不是取來之後在畫面上藏起來
- **面板不放標題**：移除 `#exp-title` 與多商品時的 `.exp-title`；面板只剩段落標題（藥丸）、內文與「複製全部」
- **移除 `.exp-sec` 包裝層**：一個商品只剩一段，`.exp-h` / `.exp-b` 直接放進 `.exp-item`；多商品之間的分界由既有的 `.exp-item + .exp-item` 分隔線承擔
- **ZIP 內只有圖片**：移除內文 `.txt`，連同「有內文時單張也打包」這條例外一起拿掉，回到單純的「單張不打包」
- **`studio.html` 移除導覽列**；`index.html` 與 `censor.html` 的導覽列維持三項不動，另外兩頁仍連得回來

商品名稱**照舊擷取**：它餵給「用這個命名」，那條路徑完全未動。

## Impact

- Affected specs: `amiami-import`、`unified-studio`
- Affected code: `lib/amiami.js`、`studio.html`、`tools/verify/amiami.mjs`、`tools/verify/studio.mjs`、`README.md`
- 四格輸出矩陣的三條逐位元不變量不受影響：`processed()`、`compose()`、`plan()`、`item.cache` 一律未動；只有「要不要多塞一個檔案進 ZIP」這一步被移除
- **可見的損失**：多商品匯入時面板不再標明哪一段屬於哪個商品，只剩分隔線。這是移除所有商品名稱的直接結果，見 `design.md` D3

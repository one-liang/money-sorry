## Context

`outputtable`（原本是 `it => it.status === 'ready'`）是「哪些照片會進 ZIP」的唯一定義，被 `plan()`、`syncBulk()`、`bulkSet()`、`updateGo()` 四處共用，程式碼裡有註解要求這四處必須是同一個集合，否則畫面上的數字會互相矛盾。

新增「要不要下載」等於在這個集合上再切一刀，所以主要的設計問題是：**這一刀切在哪一層**。

## Goals / Non-Goals

**Goals**
- 逐張決定要不要下載，不影響已經調好的構圖與遮罩
- 未勾選的不佔序號，其餘連號重排
- 不引入任何可能造成「該遮沒遮」的新路徑

**Non-Goals**
- 不改變四格輸出矩陣與其逐位元不變量
- 不為「全不選」提供復原
- 不支援「只輸出商品說明、不輸出任何照片」

## Decisions

### D1：兩層述詞，一鍵區與輸出各用一層

```js
const decodable   = it => it.status === 'ready';        // 能不能處理
const outputtable = it => decodable(it) && it.pickOn;   // 會不會進 ZIP
```

| 位置 | 用哪個 |
|---|---|
| `plan()` 的編號 | `outputtable` |
| `updateGo()` 的張數與「含遮罩」 | `outputtable` |
| 漏遮警示（`syncBulk` 的 zero） | `outputtable` |
| **一鍵區三列的分母** | **`decodable`** |
| **`bulkSet()` 的作用域** | **`decodable`** |

**一鍵區刻意不跟著勾選縮。** 替代方案（分母跟著縮）被否決，理由有三：

1. **靜默漏網**：取消勾選兩張 → 按「套框全開」（只動到其餘的）→ 把那兩張勾回來，它們的套框是關的。使用者記得自己按過全開，而且他剛剛才看到計數顯示 `N / N` 且「全開」是點亮的。一個可逆的勾選操作在另一個開關上留下了不可逆的副作用。
2. **全不選會讓一鍵失效**：分母變 0 → 兩列顯示「—」、按下去只有回彈。清單裡明明有 14 張照片。
3. **雙分母無從解釋**：三列並排卻有兩種分母，畫面上沒有任何線索說明為什麼。

固定分母的代價是分母包含不會下載的照片。這反而誠實——它們隨時可以勾回來，而勾回來時套框與遮罩已經是對的。原本那條「四處共用同一個集合」的不變量升級為：**一鍵區＝`decodable`，輸出＝`outputtable`，跨層混用就會出現互相矛盾的數字。**

### D2：偵測不看勾選

`runDetections()` MUST NOT 過濾未勾選的照片。

加上過濾會製造一條漏遮路徑：取消勾選 → 偵測略過 → `detect` 停在 `idle` → 勾回來時沒有任何人重跑偵測 → 該張遮罩開著但 `boxes` 是空的 → 輸出一張沒有遮罩的圖。而清單 badge、預覽細節、漏遮警示三個回饋管道對 `idle` 狀態全部沉默。

代價是替不會下載的照片白跑偵測。**這是刻意用算力換掉一條靜默失效的路徑**——取消勾選是輕量可逆的視圖操作，不該讓它決定一件「不做就會漏遮」的事。

只有偵測結束的統計文字改為只計會輸出的張數，讓它與一鍵區、下載按鈕對得上。

### D3：核取方塊而不是第三顆晶片

`.chips` 是直向排列，加第三顆會讓每列長高約 29px（30 張就多捲 870px）。核取方塊放在序號前面，列高完全不變。

語意上也更對：套框與遮罩回答「怎麼處理」，勾選回答「要不要」，本來就不是同一層的決定。位置也對——序號就是輸出順序，「會不會有序號」該緊鄰著它。

實作上比照 `.grip` 的既有手法：視覺 20×20，命中區用 `::before` 撐到 44×44。

### D4：不清快取

`togglePick()` 與 `bulkSet('pickOn', ...)` MUST NOT 清除 `item.cache`。勾選與否不改變合成結果，已經編好的 blob 仍然有效，勾回來時不必重編。

### D5：狀態一律由 `markRow()` 同步

核取方塊的視覺狀態 MUST NOT 只在建立元素時寫死。`render()` 會整欄重建 `<li>`，而追加檔案與模型載入失敗都會呼叫它——寫死會讓已取消的勾選被靜默還原。

### D6：不為「全不選」提供復原

既有的復原只掛在「遮罩全關」上，判準是「唯一可能造成漏遮的一鍵動作」。「下載全不選」不漏遮、後果立即可見（整欄序號變 `–`、按鈕文案改變）、一鍵即可還原，因此不需要。

但 `bulkSet()` MUST 在開頭撤掉待復原的提議。這順帶修掉一個既有瑕疵：「遮罩全關」之後按「套框全開」，那顆復原按鈕還掛著，看起來像是可以復原套框。

## Risks / Trade-offs

- **未勾選與解碼失敗在視覺上都是 `–`** → 未勾選另外標示「不下載」badge，且 aria-label 分成「未勾選下載」與「不會輸出」兩種說法
- **調了半天才發現那張沒勾** → 預覽區在未勾選時明講「這張沒有勾選下載，不會輸出」
- **序號位數會隨勾選數縮放**（14 張取消到 9 張，檔名從 `-01` 變 `-1`）→ 既有行為（壞檔也會造成），只是發生頻率變高，不另外處理
- **有商品說明但一張都沒勾** → 輸出按鈕停用並顯示「未勾選任何照片」。不支援只輸出 `.txt`，那是另一個功能

## Migration Plan

單向新增，預設全選，因此不使用時行為與先前完全相同。Rollback 即為移除核取方塊、一鍵列與 `pickOn`，並把 `outputtable` 還原成單層。

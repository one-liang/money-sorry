## Context

這批改動全部落在呈現層。輸出管線（`plan()` → `compose()` → `makeZip()`）與四格輸出矩陣的三條逐位元不變量一律不碰，`processed()`、`item.cache`、`decodable` / `outputtable` 兩層述詞的語意也維持原樣。

真正需要決定的有五件事。

## Decisions

### D1：一鍵區用三態 toggle，不是兩顆分段按鈕

原本一列是「標籤 · 計數 · [全開][全關]」，`.count { flex: 1 }` 把兩端撐開，中間那段留白在寬欄裡有一百多 px。改成 toggle 在左、標籤與計數在右且上下疊放，一列的內容因此靠左收成一塊。

語意跟著變：分段按鈕是兩個**冪等動作**，toggle 是一個**狀態**。

| 目前狀態 | 按下去 |
|---|---|
| 全開 `true` | 全關 |
| 全關 `false` | 全開 |
| 混合 `mixed` | 全開 |

這是「全選」核取方塊的標準語意。它順帶消掉了一條既有的複雜度：原本的規格特別要求「已在目標狀態時按下為無操作，但要給視覺回應（回彈動畫），且不得停用按鈕以免焦點掉出文件流」。toggle 沒有這個狀態——每一次按下都真的改變了什麼，所以 `pulse()` 與那條規則一併移除。

**用 `role="checkbox"` 而不是 `switch`。** ARIA 1.2 明文不允許 `switch` 使用 `aria-checked="mixed"`，而混合在這裡是常態而非例外。逐列的選取方塊也是 `role="checkbox"`，兩者語意一致。

`aria-checked` 同時是視覺狀態的唯一來源：CSS 掛在 `[aria-checked="…"]` 上，點擊處理器也讀它決定要開還是要關。狀態沒有第二份副本。

### D2：移除常駐的漏遮彙總條

「有 N 張開了遮罩卻一個部位都沒抓到」原本在一鍵區有一條常駐警示。移除它是使用者的決定，這裡記下取捨：

同一件事仍有兩個管道——該列的紅色「未偵測」標示，以及選到那張時預覽區的警示條。失去的是**彙總**：清單一長，要知道總共有幾張漏了就得自己掃過整欄。

輸出按鈕上的「N 張含遮罩」不變，它仍然只計實際會畫上遮罩的張數，所以「開了 5 張遮罩但只有 3 張含遮罩」這個落差在下載前仍然看得到。

### D3：模型狀態列改為浮動，不佔版面流

原本 `display: none` → `flex`，第一次開遮罩時整個 `.grid` 被往下推。改成 `position: fixed` 貼在視窗底部，顯隱走 `opacity` + `visibility`——fixed 本來就不參與版面流，位移因此歸零。

就緒 4 秒後自動收起（`show` 移除，但 `ready` 這個**狀態** class 保留）。**失敗不自動收起**：那句話同時說明了「所有遮罩開關已被退回關閉」，收掉會讓使用者不知道自己的設定為什麼變了。

### D4：sticky 掛在整個側欄上，不是掛在預覽面板上

```css
@media (min-width: 961px) {
  #side {
    position: sticky; top: 14px;
    max-height: calc(100dvh - 28px);
    overflow-y: auto;
    scrollbar-gutter: stable;
  }
}
```

**掛在內層面板上是錯的。** 第一版把 sticky 掛在 `#side > .panel:first-child`（預覽面板），結果商品說明是它的**靜態兄弟**，而 sticky 是定位元素——捲動時商品說明整片滑進預覽面板底下被蓋掉。掛在側欄本身，兩張卡就永遠一起走。

這也順帶消掉了第一版需要的 `align-self: stretch`。兩者的包含區塊不同：

| sticky 掛在 | 包含區塊 | 需要 stretch？ |
|---|---|---|
| 內層 `.panel` | `#side` 的內容框（`align-items: start` 下只有內容那麼高） | 要，否則沒有 travel 空間 |
| `#side`（grid item） | **格線區域**＝整列的高度 | **不要**，拉伸反而讓它填滿整列而失去浮動 |

**`max-height` 不能省。** 預覽面板在 420px 欄寬下約 620px 高，加上商品說明遠超過 1366×768 的視窗，沒有它「打包下載」與商品說明會被卡在視窗外。用 `dvh` 而非 `vh`，因為手機瀏覽器的網址列會吃掉 `vh` 算進去的那一段。

### D5：預覽提示拆成三個強度

| 訊息 | 落點 | 形式 |
|---|---|---|
| `3 個遮罩（胸）· 遮蓋 8.2%` | `#detail` | 淡色小字 |
| `未偵測到任何部位…` / `遮蓋過多…` / `兩個開關都關…` | `#alert` | 有底色與圖示的警示條 |
| 這張沒有勾選下載 | `#stage.unpicked` + `#offtag` | 照片淡化去彩 ＋ 角落標籤 |

第三項刻意講在**照片本身**上而不是底下的文字裡：那句話的作用是阻止使用者在一張不會輸出的圖上調構圖與遮罩，寫在圖下面太容易被忽略。

三個落點 MUST 由同一個函式一起寫，而且每條路徑都要把另外兩個歸零。少清一個就會留下上一張的警示，而它看起來完全像是這一張的——`drawPreview()` 原本各自手動清 `#detail` 的三個地方因此改為一律呼叫 `updateDetail()`。

### D6：左欄一張卡＝一個功能群組

原本五個群組擠在同一張大白卡裡，`#import` 與 `#bulk` 各自有 `border-top`，`#naming` 什麼都沒有——分隔線時有時無，讀起來是混在一起的一片。

改成四張 `.panel`，與右欄已經在用的卡片語彙一致，`.panel + .panel { margin-top: 18px }` 是唯一的卡間距數字。`#import` 與 `#bulk` 自己的 `border-top` 一併移除：卡片邊界已經在做分區，留著會變成雙重分隔。

**歸屬依「作用在什麼上」而不是「從哪裡來」**：

- `#imp-name` 從匯入區搬到**輸出設定**卡。「用這個命名」寫的就是正下方那個 `#oname`——原本兩者隔了一整個命名區塊，按下去的效果發生在畫面的另一端。
- `#clear` 從最上面那張卡的標題列搬到**照片清單**卡。它清掉的就是那份清單。

`.imphead` 這個元素消失，角色由卡 2 的 `h2` 接手。`.bulkhead`（「整批套用」）保留——它在卡 4 內部是次級標題，不是卡片標題。

可見性多了一層：`updateGo()` 除了原本的 `namingEl` / `bulkEl` / `clearBtn`，還要開關兩張卡。輸出設定卡的條件是 `namingEl.hidden && impNameEl.hidden` 而不是 `empty`——匯入拿到了商品名稱但一張圖都沒成功時，那個名稱仍可拿去命名。`showName()` 因此 MUST 呼叫 `updateGo()`，否則匯入完成時那張卡不會打開。

### D7：商品說明的標題就是商品名稱

原本 `h2` 寫著「商品說明」（只描述容器），真正的商品名稱卻用 `600 13px` 擠在下面，跟內文的 `13px` 幾乎一樣——最該一眼看到的東西被降級了。

改成商品名稱本身當標題。但**不能直接用 `.panel h2`**：那是「小標籤」樣式（`--fs-label`、`letter-spacing: .08em`、`uppercase`、`--muted`），套在日文商品名上會變成一串灰灰的疏排字。所以這個面板用自己的 `.exphead` 標題列。

三個層級刻意用**三種不同手段**拉開，不只靠字級——既有級距相鄰兩階只差 0.5px（body 13 / lead 13.5），光調字級等於沒調：

| 層級 | 手段 |
|---|---|
| 商品名稱 | `700 15.5px`（`--fs-action`，級距內既有的一階）＋ 咖啡色 ＋ 位置是標題列 |
| 段落標題（製品仕様／解説） | **藥丸標籤**，配色沿用清單 `.badge.warn` 的 `#fdf0da` / `--warn` |
| 內文 | 不動 |

`products` 會跨多次匯入累積（`push`），一個標題容不下 N 個名字，所以只有 `products.length === 1` 時名稱才升格為標題並從內容中省略；多個商品時標題改講件數，名稱回到各自那一塊上。

### D8：匯入進度長在按鈕上

`#imp-status` 原本一行文字兼差兩種性質完全不同的東西：會一直改寫的**進度**（`搜尋中…` / `下載圖片 3 / 11…`）與停在那裡的**結果**（`找到 3 筆，請選擇` / `已匯入 11 張` / 失敗原因）。匯入最久可能一分鐘，而那段時間畫面上只有一行跳來跳去的字。

第一版做成一條三段式的獨立進度條，**但它自己就是 CLS 來源**：平常 `display: none`，忙碌時才出現，6px 高 ＋ 6px margin ＝ 12px；而且它在卡片裡，卡片跟著長高，底下的「輸出設定」與「照片清單」兩張卡一起被往下推。這正是 D3 才剛替模型狀態列修掉的那一類問題。

改成**進度長在按鈕上**。按鈕本來就佔著那個位置，忙不忙都一樣大，位移天然為零：

- **spinner** 表示「還在忙」
- **按鈕內緣底部一條 3px 的線** 表示推進到哪，三個步驟壓成單一比例，權重 `search 0–.25 / detail .25–.5 / images .5–1`（圖片佔一半，它實際最花時間）
- **`#imp-msg`** 承載一行極短的文字（`搜尋中` / `通過驗證 2 / 4` / `4 / 11` / 結果 / 錯誤）。它本來就有 `min-height: 17px`，寫什麼都不位移

四個實作決定：

- **`min-width: 112px` 不是裝飾。** 「匯入」的內容寬 64px、「匯入中 ＋ spinner」是 98px；不釘住的話，旁邊 `flex: 1` 的輸入框會在每次匯入時被擠窄一次——那也是位移。這個值必須大於忙碌時的內容寬，`[13d]` 有一條斷言在守。
- **用 `transform: scaleX()` 而不是 `width`。** 圖片階段每下載一張更新一次，改 `width` 會每幀重排。
- **比例未知時來回掃，不給假百分比。** 搜尋與商品頁剛送出時我們真的不知道要多久，填一個「大概 30%」是在騙人。`prefers-reduced-motion` 下停成靜態。
- **忙碌不套用 `:disabled` 的半透明。** 按鈕在忙碌時確實是 `disabled`（防重複送出），但褪成 50% 看起來像壞掉，所以 `#imp-go.busy:disabled { opacity: 1 }`。

**行為變更（相對於第一版）**：獨立進度條時「失敗停在原地不歸零」是對的；長在按鈕上就不成立——流程結束後按鈕必須回到可按的樣子，底下卻掛著一條停住的線很怪。改成結束即歸零，失敗的位置由 `#imp-msg` 的文字承擔（它本來就會講「**搜尋**失敗」「**擷取商品頁**失敗」），階段資訊沒有遺失。

**這一批只動 UI。** `lib/amiami.js` 完全不碰，用的是它既有的兩個回呼 `onWait(n, total)` 與 `onProgress(done, total)`。「取消」按鈕與 Cloudflare 等待策略的修正需要動到請求層（`AbortController`、全域節流、等待階梯），留在另一支分支——只做 UI 的取消按鈕在重試階梯跑完前其實什麼都停不掉，比沒有更糟。

### D9：兩個 grid 都要 `minmax(0, …)`

超長的輸出命名會把左欄撐寬、兩欄相加超出 `.wrap` 而爆版。實測 1280px 下左欄從 732px 變成 770.9px，加上 gap 與右欄共 1218.9px，塞不進 1180px 的容器。

原因是 grid 軌道的**自動最小尺寸**：`1fr` 等同 `minmax(auto, 1fr)`，而 `auto` 作為下限會解析成內容的 min-content。清單的檔名籤是 `white-space: nowrap` 的，於是整條左欄的下限被它撐大。

要修**兩個地方**，第一個修完會發現第二個：

| 位置 | 原本 | 改成 |
|---|---|---|
| `.grid` | `1fr 420px` | `minmax(0, 1fr) 420px` |
| `#list` | `display: grid`（隱含 `auto` 軌道） | 明確 `grid-template-columns: minmax(0, 1fr)` |

只修 `.grid` 的話欄寬是對了，但 `#list` 那條沒指定欄的隱含軌道仍然由內容決定寬度，`<li>` 會直接超出面板（實測 1024px 下欄寬 536、列寬仍是 732.9）。

檔名籤另外加 `max-width: 100% + min-width: 0 + text-overflow: ellipsis`。**`min-width: 0` 不能省**——flex 項目的自動最小尺寸也是 min-content，光給 `max-width` 壓不住 nowrap 的文字。完整檔名掛在 `title` 上，截斷的是顯示不是資訊。

選截斷而不是換行，是因為這條路徑很常走：「用這個命名」帶進來的 amiami 商品名經常 40 字以上，換行會讓**每一列**都長高兩三行。

## Risks / Trade-offs

- **失去漏遮的彙總視角** → 見 D2；逐列標示與預覽警示保留
- **編輯模式的操作說明搬進頁尾摺疊區** → 第一次用的人在編輯遮罩時畫面上沒有指引。與先前對匯入說明、命名說明的處置一致
- **縮放列浮在照片上會蓋住右下角一小塊** → 半透明加模糊，且構圖可以拖曳避開；換得檔名獨佔一行成為圖說
- **sticky 面板內部可捲** → 滾輪在照片上被縮放攔截（僅構圖模式），其餘位置正常捲動面板

## Migration Plan

純呈現層改動，沒有資料格式或輸出行為的變更，不需要遷移。Rollback 即為還原 `studio.html` 與 `tools/verify/studio.mjs`。

## Context

這批改動全部是**移除**。沒有新的呈現元件、沒有新的資料來源，輸出管線（`plan()` → `compose()` → `makeZip()`）除了「不再多推一個 `.txt` 進 `files`」之外一行未動。

要決定的只有四件事：規格段落在哪一層被挑出來、面板剩什麼、多商品怎麼分辨、以及三頁之間的連結怎麼收。

## Decisions

### D1：`解説` 在資料層就排掉，不是在畫面上藏起來

兩種做法都能讓畫面上看不到解説：

| | 抓全部、畫面只畫規格 | 只抓規格 |
|---|---|---|
| 面板 | 一樣 | 一樣 |
| 「複製全部」 | 要記得過濾，漏了就把解説也複製走 | 不可能出錯 |
| `products[]` | 帶著永遠用不到的字串 | 只有會用到的 |
| 之後新增落點 | 每一個都要重新記得過濾一次 | 預設就是對的 |

選後者。過濾規則放在**唯一的入口**（`loadProduct()`），下游沒有第二個地方需要知道「有些段落不該用」。

`parseExplain()` 本身**不動**——它是「把 `#explain` 解析成段落」這件事的純函式，被離線樣本完整覆蓋。挑段落是另一件事，所以是另一個函式 `parseSpec()`，它建立在 `parseExplain()` 之上。

### D2：規格段落先認 id，再認標題文字

商品頁的規格內文帶著 `#detail_detail__item_spec` 這個 id。它與標題文字 `製品仕様` 相比：

- **id 是結構**——站方改版時會跟著模板走，不會為了文案微調而變
- **標題文字是顯示內容**——`製品仕様` 隨時可能變成 `商品仕様`、`スペック`，或前後多一個全形空格

所以先用 id 找，找不到才退回 `/仕様/` 的標題比對。兩條路都落空就回空陣列，走既有的「未取得內文（圖片不受影響）」——這個失敗狀態本來就在，而且看得見。**不做的事**：找不到規格時退而取第一段充數。那會讓解説在某次站方改版後悄悄回到面板上，而且沒有任何訊號。

### D3：面板不放商品名稱，代價是多商品沒有標籤

`refine-studio-ui` 當時把面板標題定為「商品名稱本身」，理由是「別用只描述容器的字」。那個理由仍然成立，但前提變了：商品名稱現在有更好的落點——左欄「輸出設定」卡上的匯入名稱，旁邊就是「用這個命名」。同一個字串在兩欄各出現一次，右邊那次不能被點、不能被用。

移除之後，多商品匯入時面板變成「兩塊沒有標籤的規格」。這是真實的損失，記錄取捨：

- 分界仍在——`.exp-item + .exp-item` 的分隔線是既有的，保留
- 多商品匯入本來就是少數情況（一次一個 JAN 是常態）
- **不發明替代標籤**（例如改標 `gcode`）：那等於把剛移除的東西換個字重新加回來。真的需要時再加，且應該由使用情境驅動，不是由「這裡看起來空空的」驅動

### D4：內文只有一個落點，就是面板

原本是兩個落點取同一份文字（面板、ZIP 內的 `.txt`）。移除後者的判準是**這份文字要去哪裡**：它最終會被貼進賣場的欄位。

- 面板 → 按「複製全部」→ 貼上。三步
- ZIP → 解壓 → 找到 `.txt` → 開啟 → 全選 → 複製 → 貼上。六步

第二條路唯一贏的情境是「離線保存一份」，而那不是這個工具在做的事——圖片本來就存下來了，說明頁隨時可以再開。

順帶消掉一條例外規則：原本「有內文時即使只有 1 張也要打包」，因為那時 ZIP 裡有第二個檔案要交付。現在 ZIP 裡只有圖片，「單張不打包」回到沒有前提的一句話。

### D5：只有 `studio.html` 拿掉導覽列

導覽列是三頁**互相**連結的，拆掉一頁的會讓連結變單向。這是刻意的：

- `studio.html` 是主力頁，進來就是要做完一整批，切走不是日常
- 另外兩頁是備援入口（`index.html` 能雙擊直接用、`censor.html` 只想遮罩時比較單純），從那裡連回主力頁**有**價值，所以它們的導覽列維持三項

結果是「兩個備援入口都指得回主力頁，主力頁不指出去」。

## Risks / Trade-offs

- **站方改掉規格段落的 id 且改掉標題文字** → 面板顯示「未取得內文」，圖片照常匯入。失敗是可見的、不影響主要工作，且離線樣本會在下次調整解析規則時擋住回歸
- **多商品的可辨識度下降**（D3）——已接受，分隔線是唯一的分界
- **習慣從 ZIP 拿 `.txt` 的流程會斷**——這是使用者自己提的移除，且面板的複製動作原本就在

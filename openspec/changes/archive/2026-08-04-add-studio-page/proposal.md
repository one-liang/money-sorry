## Why

遮罩與套框是同一批照片的前後兩道工序，現在卻分在兩頁，使用者必須「上傳 30 張 → 偵測 → 下載 ZIP → 解壓 → 換頁 → 再上傳 30 張 → 調構圖 → 下載 ZIP → 再解壓」。除了兩次上傳兩次解壓，中間還多吃了一次 JPEG 有損編碼，而且「先遮罩再套框」這條順序規則只能靠 README 提醒人腦記住——記錯了就得整批重來。

新增一頁把兩道工序併在同一次上傳裡完成，順序由程式保證，JPEG 只編一次。同時補上批次作業真正缺的東西：統一的輸出命名與序號、可拖曳的排序、可追加的選檔。

## What Changes

- **新增 `studio.html`**：左欄清單、右欄預覽的整合工作台，一次上傳同時完成遮罩與套框
- **每張照片兩個開關**（套框／遮罩），放在左欄清單每一列；清單上方為兩者各提供一組「全部開／全部關」。批次關遮罩的風險由輸出按鈕上的「N 張含遮罩」承接
- **四格輸出矩陣**：兩個開關組合出四種輸出，其中「兩個都關」為原始位元組原樣輸出，副檔名跟隨原圖
- **單次合成管線**：遮罩框以 `srcRect()` 的同一組仿射參數換算到輸出座標，與裁切、疊框在同一個 canvas 一次畫完，全程只做一次 JPEG 編碼
- **雙模式預覽**：遮罩開啟時，「編輯遮罩」看完整原圖並疊虛線裁切範圍，「調整構圖」看 1000×1000 裁切結果；兩模式視野不同，用以消除「在裁切後視野確認完成、拉遠構圖後露出未遮部位」的單向漏遮風險
- **輸出命名**：可指定名稱，套用到 ZIP 檔名、內層資料夾與各檔案（`名稱.zip` › `名稱/` › `名稱-01.jpg`）；留白則沿用原檔名。ZIP 一律開一層資料夾
- **清單可拖曳排序**，序號即時跟著重編
- **選檔改為追加**（現行為取代），並新增「清空」動作
- **遮罩面積警示改以裁切後的可見區域計算**（套框啟用時，原分母會低估遮蓋比例）
- **偵測模型延遲載入**：遮罩預設關閉，首次啟用時才下載 22MB
- **抽出 `lib/`**：`zip.js` 等共用模組由 `studio.html` 與 `censor.html` 共用，`index.html` 維持內嵌以保住單一檔案可攜性
- `index.html` **不做任何修改**；`censor.html` 行為不變，僅將重複程式碼改為引用 `lib/`

非目標：不修改 `index.html`；不改變 `censor.html` 的任何可觀察行為；不做多張拼貼版型；不新增 build 步驟。

## Capabilities

### New Capabilities
- `unified-studio`: `studio.html` 的完整行為——雙開關與一鍵、四格輸出矩陣與其逐位元不變量、遮罩座標換算、雙模式預覽、輸出命名與序號、清單排序、追加與清空、延遲載入模型

### Modified Capabilities
- `nudity-censoring`: 「獨立的遮罩頁面」目前要求 `censor.html` 與 `index.html`「MUST NOT 共用程式碼」。該條款的真正目的是保護 `index.html` 的單一檔案可攜性，需重新界定為「MUST NOT 與 `index.html` 共用」，以允許 `censor.html` 與 `studio.html` 透過 `lib/` 共用實作

`photo-framing` 不修改——`index.html` 行為完全不變，其既有需求仍然準確。`studio.html` 的套框行為由 `unified-studio` 以「輸出須與 `index.html` 逐位元相同」的方式錨定回 `photo-framing`，不重述其內容。

## Impact

- **新增**：`studio.html`、`lib/zip.js`（及其他共用模組）、`tools/verify/studio.mjs`
- **修改**：`censor.html`（僅抽換共用程式碼，行為不變，以 `tools/verify/censor.mjs` 驗收）、`index.html` 與 `censor.html` 的導覽列（新增第三個 tab）、`README.md`
- **不變**：`index.html` 的合成邏輯、`models/`、`vendor/`
- **相依**：`studio.html` 需 `http://`（模型載入），與 `censor.html` 相同；GitHub Pages 部署方式不變
- **驗證**：四格輸出中有三格可自動釘死到逐位元——「只套框」比對 `index.html`、「只遮罩」比對 `censor.html`、「都不開」比對輸入位元組本身

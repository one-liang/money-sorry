# money-sorry（錢錢抱歉 · 賣場批次套框）

把商品照批次套上「お金でごめんなさい / 錢錢抱歉」外框，一次選 N 張、輸出 N 張 1000×1000 的成品。
另附一個裸露遮罩工具，把公仔照的胸部／私處／臀部打上黑色方塊。

**照片全程留在這台電腦，三個工具都不會上傳任何檔案。**

## 三個工具，該用哪一個

| | 做什麼 | 開啟方式 |
|---|---|---|
| **`studio.html`**　遮罩＋套框 | **兩件事一次做完**，逐張決定要不要遮、要不要套框 | 必須用本機 server |
| **`index.html`**　套框 | 只套框 | **雙擊就能用**，零依賴、零 build、不需要網路 |
| **`censor.html`**　裸露遮罩 | 只遮罩 | 必須用本機 server |

**多數情況直接用 `studio.html`。** 它是另外兩頁的超集：把套框開關關掉就等於 `censor.html`，把遮罩開關關掉就等於 `index.html`，而且輸出逐位元相同（有自動驗證釘著）。

留著另外兩頁的理由各有一個：`index.html` 是唯一能**雙擊就用、可以單獨寄給別人**的單一檔案；`censor.html` 是只想遮罩時比較單純的入口。

需要 server 的兩頁沒辦法雙擊，是因為要載入一個 12MB 的偵測模型——瀏覽器在 `file://` 下把每個本機檔案當成獨立來源，會直接擋掉模型載入。`index.html` 完全不受影響，維持原本零依賴的性質。

三頁上方都有導覽列可以互相切換。

**順序很重要：先遮罩，再套框。** 套框會把圖裁成 1000×1000，先套框的話遮罩座標就對不上了。這條只在**分兩頁做**的時候要自己記——`studio.html` 由程式保證順序，而且全程只做一次 JPEG 編碼（分兩頁會編兩次，多掉一輪畫質）。

## 部署到 GitHub Pages

掛上 Pages 之後走的是 HTTPS，`studio.html` 與 `censor.html` 就不必再跑 `serve.cmd`，點連結即可使用。

設定：**Settings → Pages → Deploy from branch → `main` → `/ (root)`**。倉庫已備妥 `.nojekyll`，避免 Jekyll 處理靜態資產。

已實測確認：

| 條件 | 結果 |
|---|---|
| 掛在子路徑（`<user>.github.io/money-sorry/`） | 相對路徑正常 |
| `.wasm` 的 MIME 不是 `application/wasm` | 照樣載入（ORT 會退回 ArrayBuffer 方式） |
| 需要 COOP/COEP 標頭 | **不需要**，推論固定單執行緒、沒用到 SharedArrayBuffer |

首次造訪需下載約 **22MB**（runtime 11MB + 模型 12MB），畫面會顯示下載進度，之後走瀏覽器快取。Pages 每月流量軟上限 100GB，約可支撐數千次全新造訪。

照片依然只在瀏覽器內處理，不會上傳到任何地方——變的只是「網頁本身」來自 GitHub 而非磁碟。`test/` 已被 `.gitignore` 排除，測試素材不會被公開。

## 使用方式（遮罩＋套框，`studio.html`）

1. 雙擊 `serve.cmd`（或自己跑 `npx serve .`），開 `http://localhost:3000/studio.html`
2. 選圖或拖進來。再選一次是**加在後面**，不會清掉已經調好的東西；要重來用右上角的「清空」（要按兩下確認）
3. 左邊每一列有兩個開關，**亮＝開、暗＝關**。上面的一鍵區可以把套框或遮罩整欄開／整欄關，並且會顯示目前有幾張開著（見下方「一鍵區」）
4. 需要遮罩的話，第一次打開遮罩開關才會開始下載 22MB 的模型——整批只套框就完全不會下載
5. 逐張確認。兩個開關都開時，右邊預覽有**兩個模式**：
   - **編輯遮罩**：看到完整原圖，虛線框外的暗區是會被套框裁掉的範圍。拖曳新增遮罩、點方塊選取後可拖動、拉邊角白點改大小、選取後按 <kbd>Delete</kbd> 刪除
   - **調整構圖**：看到實際輸出的 1000×1000。外框固定不動，拖曳框裡的照片調位置，滾輪／捏合或放大鏡按鈕縮放，雙擊回到自動裁切。遮罩在這個模式是唯讀的
6. 想統一命名就填「輸出命名」，清單每一列會即時顯示自己實際的輸出檔名；留白則沿用原檔名
7. 每一列最左邊的**數字就是輸出順序**；數字右邊的**六點把手**可以上下拖曳排序，序號會即時跟著跳（把手聚焦後按 <kbd>↑</kbd><kbd>↓</kbd> 也行）
8. 按「打包下載 N 張」
9. 要重來就按右上角的「清空」，它會先變成「確定清空 N 張」並出現「取消」——不會自己逾時，一定要選一邊（<kbd>Esc</kbd> 等同取消）

### 為什麼遮罩一定要在完整原圖下確認

這是**單向**的風險：

- 構圖拉近 → 遮罩被裁掉一部分 → **安全**，露出來的區域本來就不在輸出裡
- 構圖拉遠 → 原本在畫面外、沒遮到的部位**跑進輸出** → 漏遮

所以只在「調整構圖」的畫面裡看過「都遮好了」是不夠的。編輯遮罩模式刻意顯示完整原圖並把裁切範圍標成虛線，就是為了讓畫面外的部位也看得見、遮得到。

### 四種組合

| 套框 | 遮罩 | 輸出 |
|---|---|---|
| 關 | 關 | 原始檔案**位元組原樣**轉存，副檔名跟著原圖，不重新編碼 |
| 關 | 開 | 原尺寸 ＋ 黑色遮罩（等同 `censor.html`） |
| 開 | 關 | 1000×1000 ＋ 外框（等同 `index.html`） |
| 開 | 開 | 1000×1000 ＋ 黑色遮罩 ＋ 外框 |

前三格都有自動驗證釘到**逐位元**，所以「整合有沒有動到既有行為」不必靠人眼判斷。

### 輸出命名

```
輸出命名 = 「錢錢抱歉」，共 30 張

  錢錢抱歉.zip                 ← ZIP 檔名
  └── 錢錢抱歉/                ← 資料夾（一律開一層）
        錢錢抱歉-01.jpg        ← 依清單順序編號
        …
        錢錢抱歉-30.jpg
```

- 留白就沿用原檔名（`原檔名-money-sorry.jpg`；兩個開關都關則完全不改名）
- 序號位數跟著總張數走：9 張以下 `1..9`，10~99 張 `01..30`
- 無法解碼的檔案**不佔序號**，成功的那些連號重排，不留缺號
- `/ \ : * ? " < > |` 與前後的空白、句點會被清掉；中文正常保留
- 單張仍然直接下載該檔案，不打包也就沒有資料夾

### 一鍵區

```
整批套用
  套框      30 / 30 張        [ 全開 ][ 全關 ]     ← 全開那段點亮
  遮罩      12 / 28 張        [ 全開 ][ 全關 ]     ← 混合，兩段都不亮
            ⚠ 其中 2 張沒偵測到任何部位，輸出時不會有遮罩
```

計數就是目前狀態：全部開會點亮「全開」、全部關會點亮「全關」、混合則兩段都不亮。已經在那個狀態時再按一次是無操作（按鈕會回彈一下表示有收到）。

**兩個數字都是誠實的**：
- 分母是**可輸出**的張數（無法解碼的檔案不算）
- 「含遮罩」只算**真的會畫上遮罩**的——開了開關但一個部位都沒抓到的那張，輸出時其實沒有遮罩，不會被算進去

要留意的是**遮罩的「全部關」**：它在一次點擊裡撤掉整批的遮罩。`nudity-censoring` 的取捨原則是**漏遮會被下架，多遮只是醜**，所以：

- 按下後狀態列會出現 `已關閉 28 張的遮罩　[復原]`。復原只是把開關寫回去，已偵測的框都還在，**不會重跑偵測**
- 下載按鈕一直寫著含遮罩的張數（`打包下載 30 張（12 張含遮罩）`），按下下載之前一定會看到

另外三顆按鈕（套框全開／全關、遮罩全開）沒有這層守護——它們的後果無害，不值得為了對稱而多收一次點擊。

## 使用方式（只套框，`index.html`）

1. 雙擊 `index.html`（**建議用 Safari 開**，見下方 HEIC 說明）
2. 點選或拖入商品照，可一次多張
3. 右側預覽會顯示合成結果；**點左邊清單的任一張**（或按 <kbd>↑</kbd><kbd>↓</kbd>）可切換預覽對象
4. 自動裁切一律置中，切壞的時候可以自己喬：**外框固定不動**，直接**拖曳**框裡的照片調位置，用**滾輪／捏合**或預覽下方的**放大鏡**按鈕縮放，中間的百分比（或在圖上雙擊）回到自動裁切。調整會反映在輸出上，每張各自記住，動過的會在清單標「已手動調整」
5. 按「打包下載 N 張（ZIP）」

**多張**會打包成一個 ZIP：`money-sorry-20260729-2137.zip`。
**單張**則直接給 JPG，不多包一層。

ZIP 內的檔名為 `原檔名-money-sorry.jpg`，例如 `nendoroid-front.webp` → `nendoroid-front-money-sorry.jpg`。同名的照片會自動變成 `-2`、`-3`，不會互相覆蓋。

> **為什麼是 ZIP 而不是逐檔下載**：Safari 會**靜默丟棄**間隔太短的連續程式化下載——實測 5 連下載只有 3 個落地，被丟掉的那筆連 Safari 自己的下載紀錄都不會登記，使用者完全收不到錯誤。而 Safari 正是這個工具因為 HEIC 而推薦的瀏覽器。打包成單一下載可徹底消除這個問題（實測 5/5）。細節見 `design.md` 決策 4。

## 合成規則

```
每張照片獨立處理：

  createImageBitmap(file, { imageOrientation: 'from-image' })   ← 套用 EXIF 方向
        ↓
  偵測並去除純色留白邊 → 得到「內容矩形」
        ↓
  1000×1000 canvas
    ① 鋪白底（去背 PNG 轉 JPEG 才不會變黑）
    ② 內容矩形以 cover 置中裁切後填滿
    ③ 外框整張疊上
        ↓
  toBlob('image/jpeg', 0.92)
        ↓
  多張 → store-only ZIP（手寫，零依賴）→ 單次下載
  單張 → 直接下載 JPG
```

**cover 置中裁切**：`scale = max(1000 / 內容寬, 1000 / 內容高)`，超出的軸向左右（或上下）等量裁除。不留白、不變形。

```
836×750 的橫向照片（無留白邊）：
  scale = max(1000/836, 1000/750) = 1.333
  縮放後 1114×1000 → 左右各裁 57px → 輸出 1000×1000
```

### 自動去除純色留白邊

賣場素材常見「內容被塞在正方形畫布中間、左右（或上下）補白」的圖。這種圖原本會原樣輸出（因為它已經是正方形，cover 不裁不縮），商品在框裡顯得很小。工具會先把留白邊排除，再以剩下的內容去算 cover。

```
1000×1000，左右各約 114px 純白：
  去邊後內容 771×1000
  scale = max(1000/771, 1000/1000) = 1.297
  來源取 771×771 置中 → 輸出 1000×1000，內容填滿、比例不變
```

判定刻意保守，**寧可不裁也不要裁進內容**：

| 條件 | 作用 |
|---|---|
| 四角取樣亮度 ≥ 215 | 只認淺色留白，深色純底照不會被吃掉 |
| 四角之間通道最大差 ≤ 12 | 白／米色／淺灰都吃得到；四角落在內容上則放棄 |
| 只修單軸（左右**或**上下） | **四邊都有留白＝純色底商品照，不動它** |
| 整列／整行全為背景才算留白 | 遇到任一內容像素就停，不用逐點 bounding box |

有去邊的照片會在左邊清單標示「已去左右白邊」／「已去上下白邊」，方便掃一眼確認有沒有誤判。判定門檻的取值理由與實測數據見 `openspec/changes/archive/2026-07-29-trim-margins-and-click-preview/design.md`。

> 去邊後若內容不是正方形，填滿 1000×1000 仍然只有三種結局：裁掉、留白、變形。本工具選擇**置中裁掉**——上例會從上下各捨去約 148 輸出像素。頂天構圖（例如頭頂貼齊上緣）會被切到，預覽可逐張檢查，切壞的那幾張直接在預覽上拖曳補救。

## 已知限制

- **外框橫幅會蓋住照片的左上角與右下角**（各約 52% 寬 × 10% 高）。這是外框設計本身的性質，商品主體請盡量置中。完全不會被蓋到的區域是 `x 21..978 / y 89..892`。
- **來源照片短邊建議 ≥ 1000px**。小於這個尺寸會被放大而略糊（例如 750px 需放大 33%）。工具不會因此拒絕該檔。去留白邊會讓實際放大倍率更高，效果同理。
- **去留白邊只處理純色、單軸的留白**。漸層留白、帶陰影或浮水印的邊、以及只有單邊有留白的圖都不會被處理；四邊都是淺色底的棚拍照也刻意不處理，避免貼著商品裁。
- **HEIC 只有 Safari 能解碼**。Chrome / Firefox 選到 iPhone 的 `.heic` 會標示失敗並提示改用 Safari，但不影響同批其他檔案。
- 不做多張拼貼版型，也不做自由拖拉定位。一張照片進、一張成品出。

## 換外框

外框有兩個載入路徑，換框時**兩個都要顧到**：

| | 怎麼載外框 | 為什麼 |
|---|---|---|
| `index.html` | base64 data URI **內嵌在 HTML 裡** | 在 `file://` 下，Chrome 把每個本機檔案視為獨立的 opaque origin，用 `<img src="assets/frame.png">` 載入後繪入 canvas 會使 canvas 被 taint，接著 `canvas.toBlob()` 會拋出 `SecurityError` |
| `studio.html` | 直接讀 `assets/frame.png` | 這頁本來就跑在 `http://`，同源圖片不會 taint，沒必要再內嵌一份 41KB |

（使用者選的照片走 File API 不會有 taint 問題，唯獨磁碟上的外框資產會。）

所以換框時 `studio.html` 不必動，只要換掉 `assets/frame.png`；`index.html` 則要一併更新內嵌的 base64。兩者必須是同一張圖，否則兩頁的輸出會不一致——`tools/verify/studio.mjs` 的第一個不變量會直接抓到。

要換框時：

```bash
# 1. 換掉來源外框
cp 新外框.png assets/frame.png

# 2. 產生 base64
base64 -i assets/frame.png | tr -d '\n' | pbcopy

# 3. 編輯 index.html，把 FRAME_DATA_URI 這行的 base64 換成剪貼簿內容
#    const FRAME_DATA_URI = 'data:image/png;base64,<貼在這>';
```

若新外框不是 1000×1000，同時把 `index.html` 裡的 `const SIZE = 1000;` 改成新的邊長即可（cover 計算會自動跟著走）。

# 裸露遮罩（censor.html）

把公仔照的胸部、私處、臀部自動打上黑色方塊，可以手動增減。輸出維持原尺寸，之後再丟進套框工具。

## 使用方式

1. 雙擊 `serve.cmd`（或自己跑 `npx serve .`）
2. 開 `http://localhost:3000/censor.html`
3. 選圖或拖進來，會自動偵測並套上黑方塊
4. **逐張確認**，不對的地方直接在圖上調整：
   - 空白處**拖曳** → 新增遮罩
   - **點方塊** → 選取後可拖動
   - **拉邊角的白點** → 調整大小（四角改兩邊、四邊中點只改一邊）
   - 選取後按 <kbd>Delete</kbd> → 刪除
5. 按「打包下載 N 張（ZIP）」

## 遮什麼

不判斷「這張圖露不露」，而是**定位解剖部位**——所以下面這些狀態一律都遮：

| 狀態 | 會遮嗎 |
|---|---|
| 真的露點／全裸 | ✅ |
| 原廠用光暈糊掉的部位 | ✅ |
| 原廠貼紙（愛心之類）蓋住的部位 | ✅ |
| 比基尼、丁字褲、內褲 | ✅ |
| 薄衣、極少布料 | ✅ |

## 實測命中率（31 張公仔商品照）

| 部位 | 表現 |
|---|---|
| **胸部** | 幾乎 100%，最穩定 |
| **臀部** | 良好 |
| **私處** | **最弱**——模型常常整個看不到，靠「幾何補框」補救 |

**幾何補框**：偵測到左右兩個胸部框、卻沒偵測到下體時，工具會依人體比例推算胯部位置並強制補一個框。這是必要機制，不是優化——實測那些漏掉的下體，就算把信心閾值降到 0.10 也依然是零候選，模型是**根本沒看到**，不是沒把握。

補出來的框用**黃色虛線**標示，位置不對就刪掉。代價是它有時會補在不需要的地方（例如裙子已經蓋住的坐姿），這是刻意的取捨：**漏遮會被下架，多遮只是醜**。

## 三種警示

| 清單標示 | 意思 |
|---|---|
| **未偵測** | 整張沒抓到任何部位。可能真的不用遮，也可能是漏了——工具分不出來，**一律請你自己看過** |
| **遮蓋 NN%** | 遮罩面積過大。多半是特寫照，遮住要害就等於遮掉整張圖，建議換一張角度 |
| **含推算** | 有幾何補框，請確認位置 |

## 已知限制

- **不保證通過任何平台的審核。** 這個工具遮的是解剖部位，不是在判斷合規性。
- **私處召回只有一半左右**（未計入幾何補框）。務必逐張確認，不要整批丟了就走。
- 偶爾會有框落在無關的背景上，刪掉即可。
- 只做黑色實心方塊，不做馬賽克、模糊或跟隨輪廓的非矩形遮罩。
- 遮罩**必須在套框之前**做。

## 驗證

```bash
cd tools/verify
npm install                    # 第一次要裝 playwright
npx playwright install chromium-headless-shell

cd ../..
node tools/verify/studio.mjs           # 遮罩＋套框整合頁
node tools/verify/censor.mjs           # 遮罩工具；預設吃 test/ 裡的圖
node tools/verify/preview-adjust.mjs   # 套框工具的手動構圖調整
```

`studio.mjs` 的重點是**證明整合沒有動到既有路徑**。兩個開關組出的四格裡有三格可以釘到逐位元，而且因為 `index.html` 與 `censor.html` 都還在現役，基準不必從 git tag 撈——直接跑那兩頁就是基準：

| 組合 | 基準 |
|---|---|
| 套框開 · 遮罩關 | 與 `index.html` 的輸出 SHA-256 相同 |
| 套框關 · 遮罩開 | 與 `censor.html` 的輸出 SHA-256 相同 |
| 兩者皆關 | ZIP 內的位元組與來源檔案相同 |
| 兩者皆開 | 沒有基準——預覽截圖與輸出 JPEG 的像素比對（實測平均差約 2.8/255） |

其餘還會檢查：`file://` 防呆、只套框全程不下載模型與 runtime、命名消毒與補零、失敗檔不佔序號、ZIP 資料夾層級與 UTF-8 檔名、追加不重置、清空兩段式確認、拖曳與鍵盤排序、雙模式視野切換與裁切範圍標示。

`censor.mjs` 會檢查 `file://` 防呆、模型載入、批次偵測、三種警示、拖曳新增／刪除／切換保留、ZIP 輸出，並把結果存到 `tools/verify/out/`。

`preview-adjust.mjs` 會檢查拖曳、縮放上下限、滾輪錨點、捏合、邊界夾制（照片永遠蓋滿外框）、每張各自記住調整，以及手機觸控與 `file://`。三個關鍵不變量：

- **沒動過的照片，輸出與上一版發布 `v1.2.0` 逐位元相同**——腳本會 `git show v1.2.0:index.html` 起一份基準頁面，實跑一次比 SHA-256
- **同樣的調整得到同樣的輸出**，拖過頭被夾住也一樣
- **預覽就是輸出**——把預覽截圖與實際產出的 JPEG 做像素比對（平均差約 2/255，構圖若不同會是 40 以上）

**注意**：Playwright 驗得了「有沒有畫出方塊」，驗不了「遮的位置對不對」——那個必須人眼看，所以腳本最後會叫你去解開 ZIP 確認。

**`lib/` 的界線**：`studio.html` 與 `censor.html` 都需要 server，沒有「單一檔案可攜」的包袱，所以共用同一份 ZIP 實作。`index.html` 刻意**不**引用 `lib/`——它必須維持雙擊即用、可以單獨寄給別人的性質，那邊留著自己內嵌的一份。`studio.html` 同理可以直接讀 `assets/frame.png`（同源 http 不會 taint canvas），不必像 `index.html` 那樣內嵌 41KB 的 base64。

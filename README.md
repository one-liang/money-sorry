# money-sorry（錢錢抱歉 · 賣場工具）

兩個各自獨立的本機工具，都不需要網路、照片不會離開這台電腦：

| 工具 | 用途 | 大小 |
|---|---|---|
| **`index.html`** | 批次套上品牌外框，輸出 1000×1000 成品 | 60KB，零依賴，雙擊即用 |
| **`censor.html`** | 批次為裸露部位加上黑色色塊遮罩，維持來源尺寸 | 約 18MB（內含姿態偵測模型），需先建置一次 |

**兩者不是管線。** 需要遮罩與需要套框是兩件互不蘊含的事——要兩者都做時，把 `censor.html` 輸出的 `masked/` 檔案再丟進 `index.html` 即可。

> 換一台電腦要建置、驗證或繼續開發 `censor.html`？看 **[`HANDOFF.md`](HANDOFF.md)**。

# 一、`index.html` — 批次套框

把商品照批次套上「お金でごめんなさい / 錢錢抱歉」外框，一次選 N 張、輸出 N 張 1000×1000 的成品。

**零依賴、零 build、純本機。** 雙擊 `index.html` 就能用，不需要 node、不需要網路，照片不會離開這台電腦。

## 使用方式

1. 雙擊 `index.html`（**建議用 Safari 開**，見下方 HEIC 說明）
2. 點選或拖入商品照，可一次多張
3. 右側預覽會顯示合成結果；**點左邊清單的任一張**（或按 <kbd>↑</kbd><kbd>↓</kbd>）可切換預覽對象
4. 按「打包下載 N 張（ZIP）」

**多張**會打包成一個 ZIP：`money-sorry-20260729-2137.zip`。
**單張**則直接給 JPG，不多包一層。

ZIP 內的檔名為 `原檔名-money-sorry.jpg`，例如 `nendoroid-front.webp` → `nendoroid-front-money-sorry.jpg`。同名的照片會自動變成 `-2`、`-3`，不會互相覆蓋。

> **為什麼是 ZIP 而不是逐檔下載**：Safari 會**靜默丟棄**間隔太短的連續程式化下載——實測 5 連下載只有 3 個落地，被丟掉的那筆連 Safari 自己的下載紀錄都不會登記，使用者完全收不到錯誤。而 Safari 正是這個工具因為 HEIC 而推薦的瀏覽器。打包成單一下載可徹底消除這個問題（實測 5/5）。細節見 `design.md` 決策 4。

## 合成規則

```
每張照片獨立處理：

  createImageBitmap(file, { imageOrientation: 'from-image' })   ← 套用 EXIF 方向
        ↓
  偵測並去除純色留白邊 → 得到「內容矩形」
        ↓
  1000×1000 canvas
    ① 鋪白底（去背 PNG 轉 JPEG 才不會變黑）
    ② 內容矩形以 cover 置中裁切後填滿
    ③ 外框整張疊上
        ↓
  toBlob('image/jpeg', 0.92)
        ↓
  多張 → store-only ZIP（手寫，零依賴）→ 單次下載
  單張 → 直接下載 JPG
```

**cover 置中裁切**：`scale = max(1000 / 內容寬, 1000 / 內容高)`，超出的軸向左右（或上下）等量裁除。不留白、不變形。

```
836×750 的橫向照片（無留白邊）：
  scale = max(1000/836, 1000/750) = 1.333
  縮放後 1114×1000 → 左右各裁 57px → 輸出 1000×1000
```

### 自動去除純色留白邊

賣場素材常見「內容被塞在正方形畫布中間、左右（或上下）補白」的圖。這種圖原本會原樣輸出（因為它已經是正方形，cover 不裁不縮），商品在框裡顯得很小。工具會先把留白邊排除，再以剩下的內容去算 cover。

```
1000×1000，左右各約 114px 純白：
  去邊後內容 771×1000
  scale = max(1000/771, 1000/1000) = 1.297
  來源取 771×771 置中 → 輸出 1000×1000，內容填滿、比例不變
```

判定刻意保守，**寧可不裁也不要裁進內容**：

| 條件 | 作用 |
|---|---|
| 四角取樣亮度 ≥ 215 | 只認淺色留白，深色純底照不會被吃掉 |
| 四角之間通道最大差 ≤ 12 | 白／米色／淺灰都吃得到；四角落在內容上則放棄 |
| 只修單軸（左右**或**上下） | **四邊都有留白＝純色底商品照，不動它** |
| 整列／整行全為背景才算留白 | 遇到任一內容像素就停，不用逐點 bounding box |

有去邊的照片會在左邊清單標示「已去左右白邊」／「已去上下白邊」，方便掃一眼確認有沒有誤判。判定門檻的取值理由與實測數據見 `openspec/changes/archive/2026-07-29-trim-margins-and-click-preview/design.md`。

> 去邊後若內容不是正方形，填滿 1000×1000 仍然只有三種結局：裁掉、留白、變形。本工具選擇**置中裁掉**——上例會從上下各捨去約 148 輸出像素。頂天構圖（例如頭頂貼齊上緣）會被切到，預覽可逐張檢查。

## 已知限制

- **外框橫幅會蓋住照片的左上角與右下角**（各約 52% 寬 × 10% 高）。這是外框設計本身的性質，商品主體請盡量置中。完全不會被蓋到的區域是 `x 21..978 / y 89..892`。
- **來源照片短邊建議 ≥ 1000px**。小於這個尺寸會被放大而略糊（例如 750px 需放大 33%）。工具不會因此拒絕該檔。去留白邊會讓實際放大倍率更高，效果同理。
- **去留白邊只處理純色、單軸的留白**。漸層留白、帶陰影或浮水印的邊、以及只有單邊有留白的圖都不會被處理；四邊都是淺色底的棚拍照也刻意不處理，避免貼著商品裁。
- **HEIC 只有 Safari 能解碼**。Chrome / Firefox 選到 iPhone 的 `.heic` 會標示失敗並提示改用 Safari，但不影響同批其他檔案。
- 不做多張拼貼版型，也不做自由拖拉定位。一張照片進、一張成品出。

## 換外框

外框以 **base64 data URI 內嵌在 `index.html` 裡**，不是從 `assets/frame.png` 載入的。

這是必要的：在 `file://` 協定下，Chrome 把每個本機檔案視為獨立的 opaque origin，用 `<img src="assets/frame.png">` 載入後繪入 canvas 會使 canvas 被 taint，接著 `canvas.toBlob()` 會拋出 `SecurityError`。使用者選的照片走 File API 不會有這問題，唯獨磁碟上的外框資產會。

要換框時：

```bash
# 1. 換掉來源外框
cp 新外框.png assets/frame.png

# 2. 產生 base64
base64 -i assets/frame.png | tr -d '\n' | pbcopy

# 3. 編輯 index.html，把 FRAME_DATA_URI 這行的 base64 換成剪貼簿內容
#    const FRAME_DATA_URI = 'data:image/png;base64,<貼在這>';
```

若新外框不是 1000×1000，同時把 `index.html` 裡的 `const SIZE = 1000;` 改成新的邊長即可（cover 計算會自動跟著走）。

# 二、`censor.html` — 批次遮罩

把商品照中裸露的胸部、胯部、臀部自動加上**純黑色塊**，維持來源尺寸與長寬比，同時保留一份完全未修改的原檔。

## 先建置一次

`censor.html` 是建置產物（約 18MB，內嵌了 TensorFlow.js 與姿態偵測模型），不進版控。第一次使用前跑：

```bash
node build-censor.js
```

模型權重已經在 `assets/model/`，**建置不需要網路**。之後雙擊 `censor.html` 即可使用，執行期同樣零網路（工具會自我檢查並在介面上顯示「網路呼叫 0 次」）。

## 使用方式

1. 雙擊 `censor.html`，等模型就緒（約 2～3 秒）
2. 選取或拖入商品照，可一次上百張
3. 工具自動偵測並產生遮罩建議，依可信度分成三級：

   | | 意義 | 你要做的事 |
   |---|---|---|
   | 🟢 | 關鍵點齊全、遮罩已推導 | 掃視確認 |
   | 🟡 | 關鍵點部分殘缺，或半身模式 | 看一眼，多半也對 |
   | 🔴 | **結構檢查未通過，沒有遮罩** | 必須手動畫框 |

4. 逐張複核：拖曳空白處**新增**、拖曳框內**移動**、拖曳角落**縮放**、<kbd>Delete</kbd> **刪除**、<kbd>Enter</kbd> **標記已處理並跳下一張**
5. 🔴 全部處理完後，「打包下載」才會解鎖

> **輸出鍵會鎖死，這是刻意的。** 漏遮一張的代價是商品下架甚至封帳號，而且是靜默失敗——自己不會發現。所以只要還有 🔴 沒處理，工具就不讓你輸出。

## 輸出

單一 ZIP，內含兩個目錄：

```
money-sorry-censored-20260730-1842.zip
├── masked/   已遮罩，維持來源尺寸與長寬比，不裁切不套框
└── raw/      完全未修改的原檔（位元組層級複製，雜湊與來源一致）
```

## 它怎麼決定遮哪裡

用 MoveNet 姿態關鍵點推導，不是靠偵測裸露本身：

```
17 個關鍵點  →  結構合理性檢查  →  正/背判定  →  沿身體軸推導矩形
                     │
                     └─ 不像人形就舉手，不硬猜
```

- **胸部帶**：一律產生
- **下半身帶**：**錨定在髖部位置**（不是肩寬的固定倍數，否則長軀幹體型會漏掉胯部），正面→胯部、背面→臀部
- **M字腿**：偵測到膝高於髖且雙膝張開時，改用膝距決定寬度
- **身體軸**：用「肩→髖」向量，所以趴跪等橫向姿勢也能正確定位

一律產生遮罩建議，**不自動判斷「這張有沒有裸露」**——穿著完整的照片由你按一下刪掉框。理由是自動判斷會有假陰性（該遮的判成不用遮），而那正是最危險的方向；刪一個框只要一次點擊。

## 已知限制

- **一張圖裡有兩尊 figure 時只會偵測到一尊**，第二尊不會有遮罩、也不會被結構檢查擋下。這是目前唯一已知的靜默漏遮路徑，遇到多尊合照請特別留意。
- **沒有「側面」這一類。** 曾經試過用 `肩寬/軀幹長` 判側面，但實測 23 張的分佈是 0.386→0.930 完全連續、沒有分界，已知正面的圖甚至比已知側面的還低——這個特徵沒有鑑別力，門檻只會製造誤判。改成正／背二分，並把正面帶寬 ×1.15 補償側身時被壓扁的肩寬。
- **趴跪／躺臥等軀幹接近水平的姿勢也一律轉 🔴。** 這類姿勢的臀部同時往兩個方向鼓出，矩形補不滿（實測只蓋到 78%）。判準是身體軸偏離垂直超過 45°，實測分得很乾淨。
- **局部大特寫（沒有臉、沒有可辨識人形）一律轉 🔴。** 判準是「沒有髖部關鍵點且臉部信心不足」。
- **`censor.html` 約 18MB**，開啟需要 2～3 秒。
- **需要 WebGL。** 沒有硬體加速時會退回 CPU 並顯示警告，速度會慢一到兩個數量級。
- 只做純黑矩形，不做馬賽克／模糊／貼圖。

## 換模型

把新的 `model.json` 與權重 shard 放進 `assets/model/`，重跑 `node build-censor.js`。若模型輸入尺寸改變，建置腳本會自動從 `model.json` 讀取，不需手改。

換完務必跑一次回歸驗證（見下）。

## 回歸驗證

演算法的參數（門檻、幾何係數）集中在 `src/censor-core.js`，那份檔案同時被 `censor.html` 內嵌與驗證工具使用——**兩邊跑的是同一份程式碼**。

```bash
cd tools/verify && npm i        # 只需一次（Playwright，僅開發時用）

node tools/verify/check-test-set.js       # 先確認 test/ 素材完整（換電腦後必跑）
npx playwright test                       # 遮罩正確性：參考成品比對、裸露區域覆蓋、全批不變式
node tools/verify/verify.js               # 對 test/ 全跑一次，與 baseline.json 比對
node tools/verify/verify.js --overlay     # 另外輸出疊圖到 tools/verify/out/ 供肉眼檢查
node tools/verify/verify.js --update      # 確認新結果無誤後，更新基準
node tools/verify/verify-output.js        # 驗 ZIP 結構、時間戳、原檔雜湊、成品尺寸
```

`npx playwright test` 是最重要的一支，它驗三件事：

1. **參考成品比對** —— `test/reference/` 放使用者手工做好的遮罩成品，我們的遮罩必須**完全包住**其中的黑色區塊
2. **裸露區域覆蓋** —— `targets.json` 裡人工標定的裸露區域必須被 100% 覆蓋（該張若已被工具舉手為 🔴 則跳過）
3. **全批不變式** —— 不會有「有裸露卻既沒遮罩也沒舉手」的圖溜出去

進新商品線時，把新素材的裸露區域補進 `targets.json`——**那是唯一能證明「沒有漏遮」的東西**。

驗證工具用 headless Chrome 開啟實際的 `censor.html`，測到的就是使用者實際會執行的管線。零 npm 相依。

**什麼時候要跑**：改動 `src/censor-core.js` 的任何參數之後、換模型之後、或是進了新商品線之後（模型是真人照訓練的，非人形／獸耳全身毛／機械體這類落在未驗證區域）。

素材放在 `test/`（不進版控，需自行放置商品照）。
